# Requirements Document

## Introduction

This document defines the requirements for an MMA and combat sports web platform. The platform serves MMA fans, amateur athletes, and coaches by centralizing news, fighter profiles, event calendars, and AI-powered training programs. It integrates external sports and news APIs for live content updates and exposes an AI assistant (chatbot) that adapts its responses and training plan generation to the user's declared role (amateur or coach). An admin panel provides oversight of users, content, and API usage.

The platform is built with Django (backend), PostgreSQL (database), and a Bootstrap/JavaScript frontend. Training programs generated by the AI are formatted using LaTeX for professional output.

---

## Glossary

- **Platform**: The MMA and combat sports web application described in this document.
- **User**: Any authenticated person using the Platform, either an Amateur or a Coach.
- **Amateur**: A User who has identified themselves as a recreational or competitive MMA practitioner.
- **Coach**: A User who has identified themselves as a sports coach managing athletes.
- **Admin**: A privileged User with access to the Admin Panel for content and system management.
- **News_Module**: The component responsible for fetching, storing, and displaying MMA news articles.
- **External_API**: A third-party sports or news API integrated by the Platform to retrieve live content.
- **AI_Assistant**: The AI-powered chatbot component that answers questions and generates training programs.
- **Training_Program**: A structured workout plan generated by the AI_Assistant and formatted as a LaTeX document.
- **Events_Module**: The component that displays fighter profiles, upcoming events, and fight results.
- **Event**: A scheduled MMA fight card or competition with a defined date and time.
- **Countdown_Timer**: A real-time display showing the time remaining until the next upcoming Event.
- **Stopwatch**: A timer tool available on the Platform for use during training sessions.
- **Admin_Panel**: The restricted interface through which the Admin manages users, content, and API monitoring.
- **Auth_System**: The authentication and authorization component handling registration, login, and sessions.
- **Session**: An authenticated user session established after successful login.

## Requirements

### Requirement 1: User Registration and Authentication

**User Story:** As a visitor, I want to register and log in to the Platform, so that I can access personalized features and save my preferences.

#### Acceptance Criteria

1. THE Auth_System SHALL provide a registration form collecting at minimum: username, email address, password, and role selection (Amateur or Coach).
2. WHEN a visitor submits a registration form with valid data, THE Auth_System SHALL create a User account and redirect the visitor to their profile page.
3. IF a visitor submits a registration form with an email address already associated with an existing account, THEN THE Auth_System SHALL display an error message indicating the email is already in use.
4. IF a visitor submits a registration form with a password shorter than 8 characters, THEN THE Auth_System SHALL display an error message specifying the minimum password length requirement.
5. WHEN a registered User submits valid login credentials, THE Auth_System SHALL establish a Session and redirect the User to the Platform home page.
6. IF a User submits incorrect login credentials, THEN THE Auth_System SHALL display an error message and increment a failed-attempt counter without revealing which field (email or password) was incorrect.
7. WHEN a User requests to log out, THE Auth_System SHALL invalidate the current Session and redirect the User to the home page.
8. THE Auth_System SHALL transmit all authentication data exclusively over HTTPS.

---

### Requirement 2: User Profile and Role Management

**User Story:** As a registered User, I want to manage my profile and declare my role, so that the Platform can personalize content and training programs for me.

#### Acceptance Criteria

1. THE Platform SHALL associate each User account with exactly one role: Amateur or Coach.
2. WHEN a User accesses their profile page, THE Platform SHALL display the User's username, email address, declared role, and saved training preferences.
3. WHEN a User submits an updated profile form with valid data, THE Platform SHALL persist the changes and display a confirmation message.
4. IF a User submits a profile update with an invalid email format, THEN THE Platform SHALL display a field-level validation error before submitting the form.
5. THE Platform SHALL allow a User to change their declared role between Amateur and Coach at any time from the profile page.
6. WHEN a User's role is changed, THE AI_Assistant SHALL apply the updated role context to all subsequent interactions within the same Session.

---

### Requirement 3: News Module — Content Fetching and Display

**User Story:** As a User, I want to read the latest MMA news fetched from external sources, so that I stay informed about the combat sports world.

#### Acceptance Criteria

1. THE News_Module SHALL fetch MMA and combat sports news articles from at least one configured External_API.
2. THE News_Module SHALL refresh news content automatically at a configurable interval not exceeding 60 minutes.
3. WHEN a User navigates to the news section, THE News_Module SHALL display articles sorted by publication date in descending order.
4. THE News_Module SHALL categorize articles into at least the following categories: General MMA, Fighter News, Event Previews, and Fight Results.
5. WHEN a User selects a news category, THE News_Module SHALL display only articles belonging to that category.
6. WHEN a User clicks on a news article, THE News_Module SHALL display the article title, publication date, source attribution, summary, and a link to the full article on the original source.
7. IF the External_API is unavailable during a scheduled refresh, THEN THE News_Module SHALL retain the most recently fetched articles and display a status indicator showing the last successful update timestamp.
8. THE News_Module SHALL complete the display of the news listing page within 3 seconds under normal network conditions.

---

### Requirement 4: Fighter Profiles

**User Story:** As a User, I want to browse fighter profiles, so that I can learn about MMA athletes and their records.

#### Acceptance Criteria

1. THE Events_Module SHALL maintain a database of fighter profiles containing at minimum: full name, nationality, weight class, professional record (wins, losses, draws), and fighting style.
2. WHEN a User searches for a fighter by name, THE Events_Module SHALL return all matching profiles within 3 seconds.
3. WHEN a User selects a fighter profile, THE Events_Module SHALL display all stored profile fields along with the fighter's past fight results.
4. THE Events_Module SHALL display fight results including: opponent name, event name, date, outcome, and method of victory or defeat.
5. IF no fighter matches a search query, THEN THE Events_Module SHALL display a message indicating no results were found and suggest checking the spelling.

---

### Requirement 5: Events Calendar and Countdown Timer

**User Story:** As a User, I want to see upcoming MMA events on a calendar and a countdown to the next event, so that I never miss a fight card.

#### Acceptance Criteria

1. THE Events_Module SHALL display upcoming Events on an interactive calendar view showing event name, date, location, and main event matchup.
2. THE Events_Module SHALL identify the single nearest upcoming Event by date and display a Countdown_Timer showing days, hours, minutes, and seconds remaining until that Event.
3. WHEN the Countdown_Timer reaches zero, THE Events_Module SHALL update the display to indicate the Event is live or has concluded and automatically advance the Countdown_Timer to the next upcoming Event.
4. WHEN a User clicks on an Event in the calendar, THE Events_Module SHALL display a detail page with the full fight card, venue, broadcast information, and any available fighter profiles for participants.
5. THE Events_Module SHALL update Event data from the configured External_API at a configurable interval not exceeding 24 hours.
6. IF an Event is cancelled or rescheduled, THEN THE Events_Module SHALL reflect the updated status within one refresh cycle and display the change prominently on the Event detail page.

---

### Requirement 6: Stopwatch for Training Sessions

**User Story:** As a User, I want a stopwatch tool on the Platform, so that I can time my training rounds without leaving the site.

#### Acceptance Criteria

1. THE Platform SHALL provide a Stopwatch accessible from the training section with start, stop, and reset controls.
2. WHEN a User activates the start control, THE Stopwatch SHALL begin counting elapsed time displayed in minutes, seconds, and tenths of a second.
3. WHEN a User activates the stop control while the Stopwatch is running, THE Stopwatch SHALL pause and retain the current elapsed time.
4. WHEN a User activates the reset control, THE Stopwatch SHALL return the elapsed time display to zero regardless of whether it is running or paused.
5. THE Stopwatch SHALL operate entirely in the browser without requiring a server round-trip for each tick.

---

### Requirement 7: AI Assistant — General Question Answering

**User Story:** As a User, I want to ask the AI Assistant questions about MMA and combat sports, so that I can get informed answers without leaving the Platform.

#### Acceptance Criteria

1. THE AI_Assistant SHALL accept free-text questions from authenticated Users via a chat interface.
2. WHEN a User submits a question, THE AI_Assistant SHALL return a response within 10 seconds under normal operating conditions.
3. THE AI_Assistant SHALL maintain conversation context within a single Session, allowing follow-up questions that reference prior messages.
4. WHEN a User's Session ends, THE AI_Assistant SHALL discard the conversation context for that Session.
5. IF the underlying LLM service is unavailable, THEN THE AI_Assistant SHALL display an error message informing the User that the assistant is temporarily unavailable and advise them to try again later.
6. THE AI_Assistant SHALL restrict responses to topics related to MMA, combat sports, fitness, and training; IF a User submits a question outside these topics, THEN THE AI_Assistant SHALL politely decline and redirect the User to relevant topics.

---

### Requirement 8: AI Assistant — Training Program Generation

**User Story:** As an Amateur or Coach, I want the AI Assistant to generate a personalized training program based on my needs, so that I can follow a structured plan adapted to my level and goals.

#### Acceptance Criteria

1. WHEN a User requests a training program, THE AI_Assistant SHALL prompt the User to provide: training goals, current fitness level, available training days per week, and any physical limitations.
2. WHEN the AI_Assistant generates a Training_Program, THE AI_Assistant SHALL adapt the content based on the User's declared role: programs for Amateurs SHALL focus on foundational technique and general conditioning, while programs for Coaches SHALL include periodization structures and athlete management guidance.
3. THE AI_Assistant SHALL format every generated Training_Program as a LaTeX document and provide a downloadable PDF export.
4. WHEN a Training_Program is generated, THE Platform SHALL save it to the User's profile for future reference.
5. WHEN a User accesses a previously saved Training_Program, THE Platform SHALL display the program content and provide the PDF download option.
6. IF a User provides contradictory or incomplete training parameters, THEN THE AI_Assistant SHALL ask targeted clarifying questions before generating the Training_Program.
7. THE AI_Assistant SHALL include in every Training_Program: a weekly schedule, exercise descriptions with sets and repetitions or duration, warm-up and cool-down routines, and a progression plan spanning at least 4 weeks.

---

### Requirement 9: Admin Panel — User Management

**User Story:** As an Admin, I want to manage user accounts from a dedicated panel, so that I can maintain platform integrity and handle support requests.

#### Acceptance Criteria

1. THE Admin_Panel SHALL be accessible only to Users with the Admin role.
2. IF a non-Admin User attempts to access the Admin_Panel URL, THEN THE Auth_System SHALL redirect them to the home page and display an access-denied message.
3. THE Admin_Panel SHALL display a paginated list of all registered Users showing: username, email, role, registration date, and account status (active or suspended).
4. WHEN an Admin selects a User account, THE Admin_Panel SHALL display the full profile and allow the Admin to change the account status between active and suspended.
5. WHEN an Admin suspends a User account, THE Auth_System SHALL immediately invalidate any active Session for that User.
6. THE Admin_Panel SHALL allow an Admin to search for Users by username or email address and return results within 3 seconds.

---

### Requirement 10: Admin Panel — Content Supervision

**User Story:** As an Admin, I want to supervise the news content displayed on the Platform, so that I can remove inappropriate or erroneous articles.

#### Acceptance Criteria

1. THE Admin_Panel SHALL display a list of all news articles currently stored in the Platform database, including title, source, category, and publication date.
2. WHEN an Admin removes a news article from the Admin_Panel, THE News_Module SHALL no longer display that article to Users.
3. THE Admin_Panel SHALL allow an Admin to manually trigger a news refresh from the External_API outside of the scheduled refresh cycle.
4. WHEN a manual refresh is triggered, THE Admin_Panel SHALL display the result of the operation including the number of new articles fetched and any errors encountered.

---

### Requirement 11: Admin Panel — API Call Monitoring

**User Story:** As an Admin, I want to monitor External_API usage from the Admin Panel, so that I can track consumption, detect failures, and stay within API rate limits.

#### Acceptance Criteria

1. THE Admin_Panel SHALL display a dashboard showing External_API call statistics including: total calls in the last 24 hours, total calls in the last 30 days, success rate, and last error message if applicable.
2. THE Platform SHALL log every External_API call with: timestamp, API endpoint called, HTTP response code, and response latency in milliseconds.
3. WHEN an External_API call returns an HTTP response code of 4xx or 5xx, THE Platform SHALL log the error and increment the error counter displayed in the Admin_Panel dashboard.
4. THE Admin_Panel SHALL allow an Admin to export the API call log for a selected date range as a CSV file.

---

### Requirement 12: Responsive Design and Accessibility

**User Story:** As a User accessing the Platform from a mobile device or tablet, I want the interface to adapt to my screen size, so that I can use all features comfortably on any device.

#### Acceptance Criteria

1. THE Platform SHALL render all pages correctly on viewport widths from 320px to 2560px without horizontal scrolling.
2. THE Platform SHALL use a responsive layout framework (Bootstrap) ensuring that navigation, news cards, calendar, and chat interface reflow appropriately for mobile, tablet, and desktop breakpoints.
3. THE Platform SHALL achieve a Lighthouse mobile performance score of at least 70 on all primary pages (home, news, events, training, chat).
4. THE Platform SHALL ensure all interactive controls (buttons, form fields, links) have a minimum touch target size of 44×44 CSS pixels on mobile viewports.

---

### Requirement 13: Platform Availability and Performance

**User Story:** As a User, I want the Platform to be reliably available and fast, so that I can access it at any time without frustration.

#### Acceptance Criteria

1. THE Platform SHALL be available 24 hours a day, 7 days a week, with a target uptime of 99.5% measured monthly.
2. WHEN a User loads any primary page, THE Platform SHALL deliver the initial server response within 3 seconds under a concurrent load of up to 100 simultaneous Users.
3. THE Platform SHALL serve all static assets (CSS, JavaScript, images) with HTTP caching headers enabling browser-side caching for a minimum of 24 hours.
4. IF the Platform experiences an unhandled server error, THEN THE Platform SHALL display a user-friendly error page and log the error with a stack trace for Admin review.
